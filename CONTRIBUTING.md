# Contributing to InfEdge SDK

## Important: InfEdge Does Not Accept Code Contributions

**InfEdge SDK does not accept external code contributions.**

This is a deliberate policy, not an oversight. In accordance with Section 5
of the Apache License 2.0, InfEdge explicitly states that it does NOT accept
any Contribution (as defined in the License) submitted by any party.

**What this means in practice:**

- Pull requests containing code will be **closed without review**.
- Patches, diffs, or code snippets sent via email, issue tracker, or any
  other channel will **not be incorporated** into the Work.
- Forking the repository and modifying it for your own use is permitted
  under the Apache License 2.0, but those modifications belong to you and
  will not be merged back into the official InfEdge SDK.

If you submit code despite this notice, you retain all rights to your
submission, and InfEdge acquires no license to use it. It will be discarded.

---

## What We Do Welcome

We warmly welcome the following forms of feedback, which do NOT constitute
code contributions and carry no licensing implications:

### 1. Bug Reports

Open a GitHub Issue with:
- RK3588 board model and kernel version
- SDK version
- Minimal reproduction steps
- Expected vs actual behavior
- Relevant logs (redact any sensitive data)

### 2. Feature Suggestions

Open a GitHub Issue describing:
- The problem you want to solve
- Your proposed approach (described in words, not code)
- Your use case and constraints

**Please describe your idea in prose, diagrams, or pseudocode — not in
compilable source code.** This keeps the suggestion as feedback rather
than as a Contribution under the License.

### 3. Documentation Feedback

Typos, unclear passages, or missing documentation can be reported as
GitHub Issues.

### 4. Questions and Discussions

Use GitHub Discussions for general questions about usage, deployment, or
performance tuning.

### 5. Commercial Collaboration

If you need custom features, dedicated models, or source-level access,
please contact us for a commercial engagement instead:

## How Feature Requests Are Handled

When you submit a feature suggestion, the following happens:

1. InfEdge reviews the suggestion.
2. If accepted, **InfEdge implements the feature internally** using its own
   engineering resources. The resulting code is owned entirely by InfEdge
   and licensed under Apache 2.0 (Community Edition) or the InfEdge
   Commercial License (Professional / Enterprise Edition).
3. Your suggestion is acknowledged in the release notes if you wish.
4. You receive no ownership claim over the resulting implementation.

This model lets you influence the product without creating any legal
entanglement around code ownership.

---

## Why This Policy Exists

InfEdge distributes both open source (Community Edition) and commercial
(Professional / Enterprise Edition) versions of the SDK. To keep the
commercial editions viable and to maintain a clean intellectual property
chain, all code in the repository must be authored by InfEdge or its
directly contracted contributors.

Accepting external code under Apache 2.0 would create a permanent, irrevocable
license to that code for all users — including commercial competitors. It
would also complicate the commercial licensing model.

This policy is common among dual-licensed open-core projects and is fully
compatible with the Apache License 2.0.
